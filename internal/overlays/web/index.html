Help

Usage and limits

Capture counts include enabled overlays across characters. Reusing a source uses one slot. A cast uses two timer slots. Expanded tracking keeps the strip’s size and requires the current addon plus /reload. Sources share one capture packet; extreme combinations can exceed it. If Capture packet too large appears, disable unused overlays to reduce capture demand. Up to 64 displays can appear at once; extra SHOW actions are omitted when full. Rules can use 80 blocks and eight nested levels. Saved rules are limited to 4 MB. Large shares need a current Lamda Engine.

Packs

Open Pack below Import and Export to create a collection or add this overlay to one. Members keep their own layout and Load filters. Values → Settings → Edit → Scope → Entire pack shares a setting across the collection. Changes and resets apply to every member. Each overlay separates those settings again. Detaching an overlay keeps its current values. A setting still used by any member cannot be deleted.

Export pack includes all members and their settings. Exporting only part of a pack creates independent overlays. Importing as New copy creates a separate collection; it never links settings or saved history to the original. Version identifies the author’s release. Save changes applies the collection atomically.

Pack updates and backups

Import an author’s complete pack and choose Import as → Update pack. Select your installed copy and review the members. Keep my choices preserves layout, colors, sounds, Load filters and compatible setting overrides. New members start disabled. Removed members stay as separate disabled overlays unless you clear that choice. Same or older versions need confirmation. Update pack changes your draft; Save changes applies it. Undo works while the manager is open.

Saving a pack update backs up the previous pack first. Pack → Backups reviews and restores a saved version, including its settings and enabled states. Restore also waits for Save changes. Extra current members can stay separately, disabled. Backups keep up to five versions total and three per installed copy; older versions expire. They contain overlay configuration, not remembered character history or screenshots. Media used by a retained backup cannot be deleted until that backup is removed.

Values and settings

Open Values to name a calculation. Choose fixed values, game data, settings, conditions or arithmetic. Add another value as an input to reuse it. IF → Value compares the result; SHOW → Insert value adds it to text. Live data → Value uses a number for progress, with an explicit maximum.

Values → Settings provides number, text, true/false and choice controls. Edit sets their names, defaults and ranges. Reset restores the default. Each overlay keeps its own settings. Calculations keep captured precision; unavailable inputs stay unknown, including under Not or ≠. Division by zero and results outside ±1 trillion are unknown. Current unit follows a unit clone; Trigger retains the event through WAIT.

Referenced values stay protected from deletion. Cycles are rejected. Up to 16 values and 16 settings per overlay, 64 expression nodes and eight levels per definition; referenced calculation work is bounded too. Unused definitions consume no watches. New referenced game sources may need Save and /reload. Preview uses sample data. Values share with version 5; recipients need an updated engine.

Display animations

Select SHOW → Dimensions & effects → Animations. Choose Start, Loop and Finish presets, then set their seconds. Loop begins after Start completes. Advanced offers easing, offsets, scale, rotation, opacity and color. Start moves from those values to the normal display. Loop moves toward them and back, or repeats. Opacity is a percentage of the display opacity. Effects keep the original group and attachment layout box; offsets use screen pixels, with positive Y down. Layout preview stays still; Test event plays the effects. Capture refreshes do not restart them; a new SHOW does. Start and Loop support 0.05–300 seconds; Finish supports 0.05–30. Finish plays from the current pose when a timer ends, HIDE runs, a condition becomes false or known visibility ends. It freezes the last display data and releases group space immediately. Unreadable conditions or progress, lost units or frames, unloading and stale capture cancel it. Motion shares use version 4; recipients need an updated engine.

Fonts and animated images

Select a text or bar SHOW block, then Dimensions & effects → Font for family, bold, italic, shadow or outline. Text size grows the letters; explicit height can clip large text. For an image, open Sprite sheet and enable it. Enter columns, rows and the number of frames. Frames run left to right, then top to bottom; First frame starts at 1. Playback can loop, play once, go back and forth, or follow Fill progress. Reverse changes frame order. Follow progress shows the whole selected frame; other modes can also clip the image using Fill. Unknown source progress hides the image. Test event animates; layout preview freezes the first frame. The in-game renderer targets 30 frames/second while animation is active; higher frame rates skip frames to keep the same speed. Persistent alerts keep their clock; a new SHOW restarts it.

Images and sounds

Use Media to upload PNG/JPG images or PCM WAV sounds. Choose SHOW → Image or PLAY → Browse. Images support fit, crop, stretch, tint and progress. Each file can be up to 8 MB; images up to 4096 × 4096, sounds up to 30 seconds. Shared overlays include their images and sounds; character screenshots stay private. Use Download for large shares. Delete unused files in Media. Referenced files stay protected. Visuals/media use share version 2; fonts and sprites use version 3. Recipients need an updated engine.

Visuals

Select SHOW, then Appearance → Dimensions & effects. Empty width/height use automatic sizing. Rotation and mirrors act around the center; groups and attachments use the unrotated box. Higher layers paint above lower layers within LamdaOverlays. Shape and bar progress can follow a source or timer; unknown source progress hides the display. Use Insert value for timer text. Bar icons occupy space inside the box.

Build an overlay

Add blocks inside a WHEN. Nest IF blocks to require every condition. Nested WHEN blocks wait for a later event. Load limits which characters and situations use the rule.

Organize by character

Use the character selector beneath the overlay name to move it into a character section. Use current character fills in your name and realm. Shared removes the character restriction; other Load conditions still apply. Character sections can be collapsed. New overlays and examples use the selected overlay’s character. Choose another opens Load for manual entry. Save changes to keep assignments; Undo reverses a move.

Delete an overlay

Select an overlay, click Delete beside Enabled, then confirm its name. Save changes to apply the deletion. Undo restores it while the manager is open. Deleting the last overlay leaves an empty library.

Save and test

Save changes writes to Lamda Engine. Preview uses sample data, ignores Load filters, and never sends actions to WoW. Enable LamdaOverlays in /lamda. New or changed watched auras need a manual /reload; other saved edits apply immediately.

Auras and sounds

Use the buff or debuff's spell ID. Choose its unit, presence, stacks, or time remaining. Unreadable auras never count as missing. Up to 16 unique auras can be watched. For a persistent display, set SHOW to While conditions are true. All enclosing IF checks and Load settings must keep matching; unreadable data hides it. With no IF it lasts until hidden or unloaded. Sounds fire once when a condition becomes true. Text alerts use the Text size slider to grow the letters in both directions. Resources support <, ≤, =, ≠, >, ≥ and At cap, using Amount or %. Current primary follows your active resource; specific choices also track secondary resources. Unsupported or unreadable values never match, including ≠. Examples include low mana and resource cap alerts.

Preview with your UI

Take a full, uncropped screenshot in WoW. In Preview, choose Screenshot…, select a character or Use current character, and choose the PNG or JPG. The realm fills in automatically. Enter manually is available for characters the engine has not seen. Each character keeps one screenshot; uploading another replaces it. Screenshots stay on this computer and are not included in exported rules. Current character follows the selected rule’s character Load filter, or your live character. Choosing a background does not change Load settings. Drag the display to place it, or use arrow keys (Shift for 10 pixels), then Save changes. Full screen gives you more room. Use the same game resolution and window size as the screenshot for accurate placement; changing either requires a new screenshot.

Share overlays

Export shares the selected overlay or all overlays as a code or JSON file. Character and realm filters are left out unless you include them; other Load filters, blocks, sounds and appearance stay intact. Screenshots and local sound files stay on your computer. Sonar requires that sound on the receiving computer. Import accepts share codes and earlier JSON exports, adds independent copies, and never replaces your library. Check Enable after import to turn the copies on, then Save changes. Otherwise they start disabled. Undo removes an import.

Find a spell

Use Search beside a spell ID. Type a name or ID, narrow by class or Buffs / debuffs, and choose a result. Arrow keys and Enter also work. IDs distinguish spells with the same name; the description can help identify the buff you want. Searching and choosing stay local until Save changes. Aura-watch changes need a WoW reload after saving. The offline English Retail index includes 31,636 spells from build 12.1.0.69933; it may omit newer or encounter spells. Descriptions show base tooltip text, with unresolved numbers shown as an ellipsis. You can still enter an ID directly. Data source and license.

Arches

Select an Arc or Ring SHOW block to edit it on the right. Fill can stay full, follow player health or a resource, or drain over the SHOW timer. One per stack reads the selected aura and adds left, right, top, then bottom arches. Set Max stacks to 2 and choose Left / right or Top / bottom, or use 4 for all four; extra stacks add inner arches. Nested places all arches on the same side. Shape controls angle, rotation, thickness, spacing and fill direction. Arches keep their position as stacks change. Appearance applies to this overlay. Missing or unreadable stacks hide the arches. Choose While conditions are true for a continuous tracker; timer fill stays full in that mode. Save changes, then reload WoW when adding or changing an aura watch.

Boss mods

WHEN includes boss timer starts, changes, pauses, resumes, stops, expiry, warnings and stage changes. IF Boss timer checks presence, pause state, time left or count; IF Boss stage compares the current stage. Select a block for provider, spell and text filters. Automatic chooses DBM first, then BigWigs. Use a spell ID when possible; timer text can vary by language.

Examples → Boss timer soon shows the next matching timer below five seconds. Automatic data follows a qualifying timer IF or the original timer from a WHEN, including pause and duration updates. Trigger keeps the event’s original values. Text supports {name}, {remaining}, {duration}, {count}, {stage}, {stageTotal} and {provider}.

Save and reload after first enabling boss tracking. Mid-fight registration, unknown fields and capture limits cannot prove a timer is missing. Up to 16 timers and eight recent events fit in the current capture; overflow is reported. Reload history does not fire alerts. Stops and expiry are separate events. These observations come from the provider’s timers, which are estimates.

Equipment

IF → Equipment checks an equipped item, slot, actual item level, item set piece count, weapon/armor type, or a saved outfit from WoW’s Equipment Manager. Select the block for a slot filter or the equipped-item picker. Item sets use set IDs; the picker can copy one from equipped gear. Saved outfits use their exact name and can ignore slots as configured in WoW. Empty slots are separate from unreadable data. Save and reload after enabling gear tracking or adding a saved outfit; up to eight outfits. Preview → Equipment supplies one occupied sample slot and a saved outfit; all other slots are empty.

Build and gear changes

Load → Build & gear adds talent, learned-spell and equipment filters with All / Any / Not. Losing a match, including unreadable data, unloads the overlay and cancels its displays and delayed actions. Clear removes these extra filters. Preview continues to ignore Load filters.

WHEN → Talents change watches the committed talent build, PvP talents and hero tree. Equipment changes watches equipped items, their levels and set membership, plus selected saved outfits. It does not watch enchants or bag contents. These events compare complete captured snapshots; initial login, reload and reconnect do not replay earlier changes. Save and reload when first adding either event. Test scene can send both events.

Talents

IF → Talent checks selection or rank. Select the block to choose a talent spell, PvP talent, hero tree or exact talent entry. Spell/PvP choices use spell IDs and Search; entry and hero tree choices use their own IDs. Learned spell checks whether the player currently knows an ability, including temporary abilities. Unreadable data stays unknown under Not. Unapplied talent changes are not treated as the active build. Up to 16 combined talent/learned-spell sources; save and reload after adding one. SHOW can use {rank} and a spell name/icon when available. Preview → Test scene → Talents supplies one sample source.

Blizzard timeline

Boss timers also support Blizzard as the provider. Automatic prefers DBM, then BigWigs, then Blizzard. Filters → Timeline source separates encounter and scripted timers; Edit Mode samples are excluded. Existing timers load without replaying their start events. Pauses and time corrections follow Blizzard’s clock. Zero time can mean queued; only Finished emits expiry. Removal alone means stopped. Restricted spell IDs or names stay unknown, so filters requiring them cannot match. Blizzard warnings retain readable fields; stages need DBM or BigWigs. Enable the timeline or warnings in WoW to make their data available.

Encounters

WHEN Encounter starts, Encounter ends, or Boss defeated responds to WoW’s encounter events. Select the block to filter its encounter ID, difficulty or end result. IF Encounter checks whether the selected fight is active, inactive, or has reached an elapsed time. Blank filters match any encounter.

Save and reload after first enabling encounter tracking. Reloading mid-fight can recover the active state; its ID and elapsed time remain unknown until WoW supplies a start event. Victory and wipe require an explicit result. Unknown data does not pass a condition, including NOT.

Automatic data follows an encounter IF or WHEN. Trigger keeps the original event through WAIT; Encounter reads the current fight. Text can include {encounterName}, {encounterID}, {difficulty}, {groupSize}, {elapsed} and {outcome}. Choose Fight timer from Examples to begin.

Combat events

WHEN → Combat event reads damage, healing, interrupts, dispels, aura changes, deaths and other events from WoW’s combat log. Select the block for source, target and spell filters. Affected spell means the interrupted or dispelled spell. IF → Event value compares the triggering amount or stack count; unknown values never match. Amount is the logged total; Effective amount subtracts overheal or overkill. Source name, Target name and event values remain tied to the original event through WAIT. Automatic display data follows the nearest data IF, then its event; Trigger and Affected spell select event data directly. Logging must be enabled in WoW (/combatlog). Log writes can be delayed; events older than three seconds are ignored. The log must belong to your current character. This does not replace native aura or cast tracking. Save and reload after selecting new units; up to eight combat units including Player. Target changes cancel output tied to the old target. Combat logs provide events, not continuous aura state. Test scene → Combat event supplies sample data.

Casts

IF → Casting checks a unit’s cast, channel, empowered cast, interruptibility or time left. Select the block to filter a spell on the right; leave it blank for any spell. WHEN has separate start, success, stop, failure and interrupt events. A stop alone never means success or an interrupt. Current unit follows FOR EACH. SHOW can use the cast name, icon and time; event alerts retain the triggering spell. Unknown data cannot satisfy Not casting. Save and reload after adding a cast unit. Casts and cooldowns share 90 timer slots: one per cooldown, two per cast unit. Brief events use a four-entry history per unit; stale events are not replayed on reconnect. Preview → Test scene → Cast provides sample data.

Cooldowns

IF → Cooldown supports spells, item IDs, equipped trinkets/weapons and the global cooldown. Ready checks cooldown and charges. Usable also checks resource and spell requirements; range and target validity are separate. Spell checks ignore the global cooldown; choose Global to check it explicitly. Charges, Full charges and Recharge apply to charge-based spells. Time left and Recharge use seconds. Preview → Test scene → Cooldown supplies sample values. Unknown data cannot trigger an alert. Save, then reload WoW after adding a new watched cooldown. Cooldowns and cast units share 90 timer slots, independently of aura watches.

Live text and icons

Select a SHOW block. Insert value adds a changing name, time, stack count, resource amount or character field to its text. Live data → Automatic follows the nearest health, resource, aura or cooldown condition, skipping role and location checks. Choose a source to track something else. Unknown values show —. Source progress uses current/maximum for resources and remaining/total for timers; health is a percentage. Charges and Recharge are separate fill modes. No expiry stays full. New aura or cooldown sources require Save and a WoW reload. Icons can follow the source or use a spell chosen with Search. Icons download by public spell ID from Wowhead and stay cached locally; rules and character data are not sent. A question mark means the image is unavailable. Search and spell names use the offline catalog.

All / Any / Not

Choose IF → Conditions and select the block to edit checks on the right. All (AND) requires every check. Any (OR) requires at least one. Not (NOT) reverses a single check or group. Add a Condition group for nested logic; expand a check to edit it. Switching a group to Not wraps its existing checks together. Empty groups and unreadable data stay unknown, including under Not. A known false can decide All, and a known true can decide Any. Up to 32 checks and four nested group levels per IF. Enclosing IF data uses a source only when the group has one unique source; choose Live data manually when combining different sources.

Appearance changes

Select a SHOW block, open Appearance changes, and add a Change. Choose its conditions, then add only the properties you want to change. All matching changes apply to this overlay; later ones win when they change the same property. False or unknown checks restore the original appearance. Sounds play once when a change starts matching while a display is active, and re-arm after it stops. Changes stay in exported overlays. Custom accent colors are also available. Actions offers one sound when the overlay first appears and another when its last display disappears, including timer expiry. Preview sounds require Play sounds during tests.

Display groups

Select SHOW → Group. Create a group or join an existing one. Keep positions moves members together; Row, Column, Grid and Circle arrange visible displays and close gaps as alerts disappear. Set spacing, sort order and direction in the group menu. Unknown sort values stay last. Drag the preview or use arrow keys to move the whole group. Each member keeps its own rules and Load filters. Choose None to detach a member; deleting a member leaves the rest. Export → This group includes all members. Imported group copies stay independent.

Frame attachments

Select SHOW → Attachment. Choose a unit frame, nameplate, common UI element or named frame. Frame point and Display point choose the edges or centers to align; X/Y are pixel offsets, with positive Y moving down. Groups attach as one arrangement. Save, then reload WoW after choosing a new frame. Missing, hidden or unreadable frames hide the attached display. No frame values are guessed. Preview → Test scene → Attachment offers a sample frame or current live coordinates. Live coordinates require the same character as the screenshot. Dragging an attached display adjusts its offsets. Named frames accept a global frame name only; /fstack in WoW can help find it. Up to 64 distinct attachments can be captured.

Unit clones

FOR EACH repeats its blocks for your party, raid, bosses, arena opponents or nameplates. Party or raid switches with your current group. Choose Current unit in conditions, live data or Attachment to follow that unit. Explicit Player and other units keep their own targets. Each watched unit uses its own source slot. New groups and sources load after Save and /reload; existing loaded sources continue working.

Known identities follow units when positions change. When an identity is unavailable, the display stays with its current slot and clears when that slot changes. Repeated references to the same known unit produce one clone within that group. Departures cancel pending actions. Group offers row, column, grid and other layouts. Preview → Test scene → Units selects a sample group and member count.

Unit readings

Health and Resource conditions have a Unit selector. Current unit follows the surrounding FOR EACH, or Player outside it. Live data can select its own unit. Arc Fill unit is separate from its stack aura unit. Preview has health, resource and aura unit choices. Up to 64 additional health/resource sources are captured, independently of aura and cooldown limits; player readings reuse the existing feed. Save and reload after adding a new source. Missing, off-screen, restricted or unreadable readings stay unknown. Remote rune counts are unavailable. Changing a target cancels delayed output tied to the previous unit. Existing loaded sources keep working when another source awaits reload.

This release

Free screen icons, text, bars, rings, arcs and sounds; nested events and conditions; character and context filters. Health, resources and selected auras support player, pet, target, focus, party, raid, boss, arena and nameplate units; player cast events are available. Dynamic display groups, sorting, frame attachments and conditional appearance are available. Party, raid, boss, arena and nameplate clones, custom media, sprite sheets, fonts and Start/Loop/Finish animations are available. Values, reusable actions, saved history and shared pack settings are available.

Remembered values

Values → Mode → Remembered captures the formula when its event and condition match. Count events builds a counter. All captures for one event read the previous values, then update together. Unknown or wrong-type readings keep the last capture. State, buff, cast and cooldown conditions capture once until false or unknown. Health and resource changes capture each matching update. Test event updates preview memory; Reset clears it.

Memory belongs to the overlay and is shared by its displays and clones. It resets when unloaded, saved, reloaded, disconnected, or when the character, spec or location changes. Combat and encounter modes also reset at their start. Keep between sessions saves history separately for each character and realm. Open Saved history to inspect or reset it. History writes about every two seconds and on normal engine shutdown; a forced exit can lose the latest unwritten updates. Temporary reset modes keep their existing behavior. Preview tests use separate temporary history. Shares include setup and initial values, never character history.

Reusable actions

Open Reusable actions in the block list. ACTION defines a named sequence at the top level. Add its steps, then place CALL inside a WHEN or IF. Each call uses its caller’s conditions, event and unit; editing the definition changes all calls in this overlay. WAIT also delays the steps after a call. Definitions are collapsed when the page opens.

Unused definitions do not run or add watches. Delete their calls before deleting a definition. Actions cannot call themselves, directly or indirectly. Shares include definitions and calls.
